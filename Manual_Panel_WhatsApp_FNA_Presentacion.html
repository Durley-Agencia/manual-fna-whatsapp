01 · Presentación y objetivos

Una guía operativa para administrar el bot conversacional

El sistema BFF (Backend For Frontend) orquesta la lógica del bot y se comunica con la API de WhatsApp Business, de modo que el panel permite configurar cada módulo sin tocar código: flujos, nodos, aristas, plantillas, activación, auditoría y reportes.

Orientar

Navegación y uso de cada módulo del panel para el administrador funcional y operativo.

Explicar y detallar

Los conceptos de flujo, versión, nodo, arista y plantilla, junto con los procedimientos paso a paso para crearlos y gestionarlos.

Describir y facilitar

El proceso de activación de versiones y su impacto en los usuarios, además de la consulta de auditoría, conversaciones y reportes operativos.

02 · Definiciones

Nueve conceptos que sostienen todo el panel

Antes de entrar a cada módulo, vale la pena fijar el vocabulario común.

Flujo

Conjunto ordenado de nodos y aristas que define una conversación completa del bot con el usuario de WhatsApp.

Versión de flujo

Iteración específica de un flujo. Cada flujo puede tener múltiples versiones, pero solo una puede estar publicada a la vez.

Nodo

Unidad de acción dentro de un flujo: enviar mensajes, capturar entradas, llamar servicios, evaluar condiciones o finalizar la conversación.

Arista (edge)

Conexión dirigida entre dos nodos que define la transición del flujo según condiciones de coincidencia.

Plantilla (template)

Texto predefinido con variables dinámicas que se usa en los mensajes del bot hacia el usuario.

Payload

Conjunto de variables de sesión que almacenan datos capturados durante la conversación: documento, teléfono, opciones seleccionadas.

Activación

Proceso de publicar una versión de flujo para que sea utilizada en producción por los usuarios reales de WhatsApp.

Panel de Administración

Aplicación web que permite gestionar todos los aspectos del bot de WhatsApp del FNA.

BFF

Backend For Frontend: la capa de servidor que orquesta la lógica del bot y se comunica con la API de WhatsApp Business.

03 · Acceso y autenticación

Entrar al panel, sesión por sesión

Requisitos previos

Navegador actualizado (Chrome, Firefox o Edge), credenciales institucionales entregadas por el administrador del sistema, y conexión a la red interna del FNA o VPN activa.

Sesión y tokens

Autenticación por JWT. El token de acceso dura 15 minutos y se renueva automáticamente; el token de refresco dura 7 días. Tras 7 días de inactividad, la sesión expira y se vuelve a la pantalla de inicio.

  1. Abra el navegador e ingrese la URL del panel proporcionada por el equipo de tecnología.
  2. En la pantalla de inicio de sesión, ingrese su correo electrónico institucional.
  3. Ingrese su contraseña en el campo correspondiente.
  4. Haga clic en el botón "Iniciar sesión".
  5. Si las credenciales son correctas, será redirigido a la página principal del panel (Plantillas).

Si las credenciales son incorrectas, el sistema muestra un mensaje de error. Tras múltiples intentos fallidos, contacte al administrador del sistema.

04 · Gestión de flujos

Flujo, versión y activación no son lo mismo

Un flujo agrupa nodos, aristas, plantillas y configuración. Cada cambio se hace en una nueva versión, nunca sobre la publicada. Haz clic en cada estado para ver su detalle.

draft
published
archived
draft (borrador)

Versión en desarrollo, no visible para los usuarios de WhatsApp. Se trabaja libremente: se agregan nodos, se configuran aristas, se ajustan plantillas y parámetros.

Listar y seleccionar flujos

Todo módulo de gestión (Nodos, Aristas, Configuración, Grafo) muestra en la parte superior un selector de flujo y versión. La selección se mantiene al navegar entre módulos.

Crear una nueva versión

Al seleccionar un flujo y pulsar "crear nueva versión", el sistema genera automáticamente una versión en estado draft con el número incrementado, lista para editar.

Nunca se modifica directamente una versión publicada: siempre se crea una nueva versión para los cambios.

05 · Gestión de nodos

Seis tipos de nodo, un mismo formulario base

Cada nodo representa un paso de la conversación. Se crea con Key, Display Name y Type; luego cada tipo tiene su propia configuración.

message

Envía un mensaje de texto al usuario. Uso principal: saludos, instrucciones, confirmaciones.

input

Solicita y captura una entrada del usuario: texto libre, selección de opciones o patrón regex.

router

Evalúa condiciones y dirige el flujo según variables del payload. No interactúa con el usuario.

service

Ejecuta una llamada a un servicio externo o API: consultar créditos, validar identidad, agendar citas.

subflow

Invoca otro flujo como subflujo y retorna al flujo principal al finalizar. Útil para procesos reutilizables.

end

Nodo terminal que finaliza la conversación. No puede tener aristas de salida.

  1. Seleccione el flujo y la versión deseada en los selectores superiores.
  2. Navegue al módulo "Nodos" en el menú lateral.
  3. Haga clic en el botón "Crear nodo".
  4. Complete Key (identificador único, minúsculas con guiones bajos: solicitar_documento, validar_identidad), Display Name (nombre legible) y Type.
  5. Haga clic en "Guardar". Requiere rol admin.

message: se configura con message_template, el nombre de la plantilla asociada creada en el módulo de Plantillas.

input: se configura mediante input_schema. Para selección de opciones: expected "choice_number" con un arreglo choices (key, label, value) y store con la clave de almacenamiento. Para texto validado: expected "regex" con pattern y store.

service: se configura con action_config: mapeo de entrada (variables del payload que se envían), mapeo de salida (cómo se guarda el resultado), manejo de errores mediante una arista de error, y valores por defecto si el servicio no responde.

router: la lógica se define en las aristas de salida, cada una con un match_type y match_value evaluado contra el payload; se recomienda una arista con match_type "any" como camino por defecto.

subflow: en action_config se referencia el flujo objetivo; al llegar a este nodo el bot ejecuta el subflujo completo y retorna al principal.

end: es terminal (is_terminal: true); en action_config se puede configurar un close_reason para registrar por qué terminó la conversación.

Para editar: en la lista de Nodos, clic sobre el nodo, se abre el formulario con los datos actuales, se realizan los cambios y se guarda. Cada edición queda registrada automáticamente en auditoría con los valores anteriores y posteriores.

La eliminación de nodos ocurre en cascada al eliminar una versión de flujo completa; los nodos individuales también pueden eliminarse desde la interfaz si el rol lo permite.

Los nodos usan variables dinámicas con sintaxis {{variable}}, reemplazadas en tiempo de ejecución con los valores del payload: por ejemplo {{documento}}, {{nombre}} u {{opcion_seleccionada}}.

06 · Gestión de aristas (edges)

El camino de la conversación se decide por prioridad

Cuando un nodo termina, el sistema revisa sus aristas de salida ordenadas por prioridad (menor número, mayor prioridad) y usa la primera que coincida.

Tipo de coincidenciaDescripciónEjemplo de match_value
anyCoincide siempre, sin importar la entrada del usuario.null o vacío
equalsCoincide solo si la entrada es exactamente igual al valor."1"
containsCoincide si la entrada contiene la subcadena indicada."ayuda"
regexCoincide si la entrada cumple el patrón de expresión regular.^[0-9]{6,10}$
numeric_rangeCoincide si el valor numérico está en el rango especificado.>18, <65
ends_withCoincide si la entrada termina con el sufijo indicado.@fna.gov.co
  1. Navegue al módulo "Aristas" y seleccione flujo y versión.
  2. Haga clic en "Crear arista".
  3. Seleccione el nodo origen (from_node_key) y el nodo destino (to_node_key).
  4. Elija el tipo de coincidencia (match_type) y el valor de coincidencia (match_value).
  5. Defina la prioridad (priority); el valor por defecto es 100, y los números menores tienen mayor prioridad.
  6. Haga clic en "Guardar". Requiere rol admin.

Las aristas pueden definir set_vars: un objeto JSON con pares clave-valor que se almacenan en el payload cuando la transición se activa, útil para registrar la opción seleccionada o marcar indicadores.

En los nodos service es recomendable configurar siempre una arista de error con match_type "any" y prioridad alta, como respaldo si la llamada al servicio falla.

Eliminar una arista puede dejar nodos sin conexión. Verifica el grafo después de eliminar para asegurarte de que el flujo siga siendo válido.

07 · Gestión de plantillas

El texto que el usuario realmente lee

Qué define una plantilla

Nombre (identificador único referenciado desde nodos message), nombre visible, idioma (por defecto "es") y contenido, con soporte para variables dinámicas {{variable}}.

Ejemplo con variables

"Hola {{nombre}}, tu número de documento {{documento}} ha sido verificado exitosamente. Tu próxima cita está programada para el {{fecha_cita}}."

  1. Navegue al módulo "Plantillas" en el menú lateral.
  2. Haga clic en "Crear plantilla".
  3. Complete el nombre (minúsculas con guiones bajos, ej. bienvenida_principal), el nombre visible, el idioma y el contenido del mensaje.
  4. Haga clic en "Guardar". Requiere rol admin.

Subir: formatos permitidos JPEG, PNG, GIF y WebP, con un tamaño máximo de 5 MB por archivo. Al cargarla, el sistema devuelve una URL para incluir en el contenido de la plantilla.

Eliminar: requiere rol admin y borra la imagen del almacenamiento de forma permanente.

Las plantillas se vinculan a los nodos message a través de message_template, y también se usan en mensajes de error, de timeout de sesión y de confirmación o cierre.

08 · Configuración del flujo

Cada versión tiene sus propios parámetros

Los parámetros se almacenan como pares clave-valor independientes por versión de flujo.

ParámetroDescripciónEjemplo
session_timeout_minutesTiempo máximo de inactividad antes de cerrar la sesión automáticamente."15"
max_retriesNúmero máximo de reintentos permitidos cuando el usuario ingresa una entrada inválida."3"
error_message_templatePlantilla de mensaje que se muestra cuando ocurre un error inesperado."error_general"
default_languageIdioma predeterminado para las plantillas del flujo."es"
enable_analyticsHabilita o deshabilita el registro de analíticas para esta versión."true"
webhook_urlURL de callback para eventos del bot.https://api.fna.gov.co/webhooks

Timeout de sesión

Al alcanzar session_timeout_minutes, el sistema envía un mensaje preguntando si el usuario desea continuar. Si no responde, envía un mensaje de cierre y marca la sesión como cerrada con motivo "timeout".

Modo básico y modo avanzado

Básico: campos amigables con valores sugeridos, recomendado para la mayoría. Avanzado (JSON): edición directa en formato JSON, útil para configuraciones complejas.

Los cambios en la configuración solo aplican a la versión seleccionada; si se necesitan los mismos parámetros en otra versión, deben configurarse individualmente.

09 · Visualización del grafo

Todo el flujo, en un solo diagrama

Qué muestra

Nodos como rectángulos con su nombre visible y tipo (cada tipo con un color distinto), y aristas como flechas dirigidas con su tipo de coincidencia y valor.

Nodo inicial y terminales

El nodo inicial suele ser "start" o el primer nodo del flujo. Los nodos terminales (tipo end) se identifican visualmente como puntos finales.

Interacción

Zoom con la rueda del ratón, pan arrastrando el lienzo, ajuste automático a la pantalla, y exportación de la estructura completa en formato JSON.

El grafo se genera automáticamente a partir de los nodos y aristas configurados. Cualquier cambio en la estructura se refleja al recargarlo.

10 · Activación y publicación

Publicar una versión afecta a usuarios reales

Solo una versión por flujo puede estar activa a la vez. Requiere rol admin.

  1. Seleccione el flujo y la versión que desea activar.
  2. Navegue al módulo de activación o use la opción "Activar" en la interfaz.
  3. Confirme la activación.

Al activar: la versión cambia de "draft" a "published", se registra la fecha y hora (published_at), y cualquier versión antes publicada del mismo flujo pasa automáticamente a "archived". Los nuevos usuarios usan de inmediato la versión recién publicada.

Impacto en usuarios de WhatsApp

Las conversaciones en curso continúan con la versión anterior hasta finalizar su sesión. Las nuevas conversaciones usan la versión recién activada de inmediato. No hay marcha atrás automática: para revertir hay que activar manualmente una versión anterior o crear una corregida.

Antes de activar, verificar

Todos los nodos conectados mediante aristas (revisar el grafo), las plantillas referenciadas existentes y correctas, los nodos service con sus mapeos configurados, al menos un nodo end, los parámetros establecidos, y pruebas internas realizadas.

Se recomienda activar en horarios de bajo tráfico para minimizar el impacto si se detecta algún problema.

11 · Auditoría

Quién cambió qué, cuándo y cómo se conversó

Cada creación, modificación o eliminación de un nodo, arista, plantilla o configuración genera automáticamente un registro de auditoría. Requiere rol admin, salvo la consulta de conversaciones.

FiltroDescripciónValores posibles
Tipo de entidadFiltra por el tipo de objeto modificado.node, edge, flow, setting, template
AcciónFiltra por el tipo de operación realizada.create, update, delete
UsuarioFiltra por el administrador que realizó el cambio.correo electrónico
Fecha inicio / finLímites del rango de fechas.AAAA-MM-DD

Qué muestra cada registro

Fecha y hora, usuario, acción, tipo de entidad, datos anteriores (before_data) y datos posteriores (after_data): suficiente para rastrear exactamente qué cambió, quién y cuándo.

Consulta de conversaciones

La pestaña "Conversaciones" muestra ID, teléfono, estado (active o closed), nodo actual, payload y último mensaje. Se puede filtrar por estado, teléfono, ID y rango de fechas.

La línea de tiempo de una conversación registra cuatro tipos de evento: transition (avance de un nodo a otro), incoming_message (mensaje del usuario), outgoing_message (mensaje del bot) y session_lifecycle (inicio, reinicio o cierre de sesión).

  1. En la lista de conversaciones, identifique la conversación activa que desea cerrar.
  2. Haga clic en "Forzar cierre".
  3. Confirme la acción.

La sesión pasa a "closed", se registra un evento transition con destino ADMIN_FORCE_CLOSE, y el motivo queda como "admin_force_close" en el payload. Úsalo solo cuando sea estrictamente necesario, por ejemplo si una conversación quedó atascada en un bucle.

12 · Reportes

Un dashboard operativo del bot

Acceso de usuarios

Tendencia diaria de usuarios que interactúan con el bot, discriminados por afiliados y nuevos.

Finalización de flujos

Por cada flujo: total de conversaciones, completadas, abandonadas, cerradas y transferidas a agente humano (handoff).

Funcionalidades más usadas

Ranking de los 10 flujos o funcionalidades más consultados por los usuarios.

Horas pico

Distribución de conversaciones por hora del día (0 a 23h), útil para identificar momentos de mayor demanda.

Distribución geográfica

Cantidad de sesiones agrupadas por departamento o región del usuario.

Filtros del dashboard

Rango de fechas y tipo de usuario: todos, afiliados o nuevos.

  1. Configure los filtros deseados (fechas, tipo de usuario).
  2. Haga clic en "Exportar a Excel".
  3. El sistema genera un .xlsx con tres hojas: Reporte Operaciones (detalle diario por flujo y estado), Consolidado (totales acumulados por flujo) e Ingresos por Identificación, opcional (sesiones individuales con usuario, fecha, hora y servicio).
  4. El archivo se descarga automáticamente en el navegador.

Todos los reportes usan la zona horaria de Colombia (America/Bogota). Los reportes grandes pueden tardar unos segundos en generarse.

15 · Anexos

El flujo de trabajo completo, y el glosario técnico

Anexo A · Flujo de trabajo típico

  1. Crear o seleccionar un flujo existente.
  2. Crear una nueva versión (draft) del flujo.
  3. Diseñar los nodos: message, input, service, router, subflow, end.
  4. Configurar las aristas entre nodos con sus condiciones de transición.
  5. Crear las plantillas de mensajes necesarias con las variables adecuadas.
  6. Ajustar los parámetros de configuración: timeout, reintentos, entre otros.
  7. Verificar el flujo en el visor de grafo.
  8. Activar la versión para producción.
  9. Monitorear las conversaciones y métricas en el módulo de Reportes.
  10. Consultar la auditoría para trazabilidad de cambios.

16 · Resumen ejecutivo

En síntesis

  • 01 El panel gestiona flujos conversacionales completos: nodos, aristas, plantillas y configuración, con dos roles (admin y viewer).
  • 02 Ningún cambio afecta producción directamente: siempre se trabaja sobre una nueva versión en estado draft.
  • 03 Activar una versión archiva automáticamente la anterior. Las conversaciones en curso terminan con la versión con la que empezaron.
  • 04 Seis tipos de nodo cubren todo el ciclo: mensaje, entrada, servicio, enrutador, subflujo y cierre.
  • 05 Las aristas deciden el camino por prioridad, con seis tipos de coincidencia disponibles.
  • 06 Toda modificación queda auditada con datos anteriores y posteriores, trazable por usuario y fecha.
  • 07 El dashboard de Reportes y la exportación a Excel dan visibilidad operativa diaria del bot.
  • 08 Sesión con tokens JWT: acceso de 15 minutos, refresco de 7 días.
